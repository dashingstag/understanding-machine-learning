# AGENTS.md

A learning journal: notes towards understanding machine learning — how
modern (2026-era) systems are built, trained, aligned, deployed and used.
See `README.md` for the method and the understanding levels.

## Rules for agents

- **`level` in `map.json` is the agent's content flag.** 0 = no page, 1 =
  content exists. Set it to 1 when you create a concept's `index.md` or
  `playback.html` (the build errors on level>1 and on level 1 with no page,
  and warns when a page exists at level 0). Levels 2-5 record the owner's
  understanding: the owner sets them with the level chip on each page, saved
  to `progress/levels.json` (gitignored) — never write them into `map.json`.
  A concept that has a page also needs `assess` in `map.json`:
  `{"2": "…", "3": "…", "4": "…", "5": "…"}` — a concept-specific
  self-assessment prompt per owner level, shown in the playback's drill panel
  (the build requires all four once content exists). It also needs `video`:
  `{id, t, title, channel, note}` — a YouTube video cued to the relevant
  segment (t in seconds; prefer high-quality explainers; note says which
  bit), shown in the bar's left-hand "Watch" popover. The build requires it
  on every page with content.
- **Leave "In my own words" for the owner.** Draft other sections, never this one.
- **Link by default.** When playback prose names a concept or a glossary
  term, wrap the phrase: `<a data-concept-link="id">` for concepts,
  `<span data-notation="id">` for glossary symbols. If the term has no entry,
  add one — a concept node in `map.json` or a glossary entry in
  `notation.json`. One link per term per page satisfies the rule; the build
  warns on unlinked mentions.
- **Cite everything.** Every claim needs a source (paper + section, official
  docs, canonical implementation) or a computation in `playground/`.
- **Keep three things distinct**: established result, what a source claims
  (e.g. a lab's blog post), and open questions. Frontier-ML claims age fast —
  date them.
- External links open in a new tab (`target="_blank" rel="noopener"`);
  internal links stay in-tab. The build scans literal `<a href="http…">`
  tags in site assets and fails without `target="_blank"`.

## Structure

- **Every playback page ships the full kit** — keep `attention-mechanism` as
  the reference: a `.aside` story/real-world card on *every* frame (they
  show in the left rail), an `.anim-panel` with a persistent animation
  (a sweep needs a manual scrub slider `id="scrub"`), the header
  **Article** + **Notes** links, `page-id.js`, lore data for name pop-ups,
  and the header search (`assets/search.js` + all three data files).
  `build.py` errors on missing kit pieces and warns on frames without a
  story aside, pages without an anim-panel, or an anim-panel without
  `id="scrub"`.
- `map.json` is the single source of truth: `id`, `title`, `summary`,
  `parents`, `level`, `why` (required per parent edge), `assess`, `video`.
  Children are derived from `parents`. Don't add `page`/`playback`.
- **Every HTML file has a page-id** — `data-page-id="<id>"` on `<body>` +
  `assets/page-id.js`; unique per folder. A playback's is its concept id.
- **The header "Notes" link is the owner's notes widget.** Keep
  `href="index.md"` — `notes.js` intercepts it (draggable panel, writes
  `notes/<page-id>.md` via File System Access). `notes/` is gitignored
  content-wise (`notes/*` + `!notes/.gitkeep`, build-checked).
- **`index.md` renders as `index.html` ("Article")** — generated by
  `build.py`; never edit it. Markdown subset only: `##`–`####`, `-`/`1.`
  lists, `>` quotes, `**b**` `*em*` `_em_`, `` `code` ``, `[t](u)`,
  `$$…$$`, fenced blocks. `` `concept-id` `` backticks link to that
  concept's playback.
- `concepts/` is **relatively flat**: shared concepts (several parents)
  stay at `concepts/<id>/`; only a single-parent concept may nest.
  `assets` subfolders hold a page's own files and are skipped.
- Links between pages: `<a data-concept-link="id">` — resolved from the
  map so folders can move.
- **Animations live outside the frames** in `<aside class="anim-panel">`
  between `</header>` and `<main>` (resizable via a left-edge grip).
  One-frame demos stay in `<div class="widget">`.
- **Stories live in the left rail** — `.aside` / `.aside real` inside the
  frame they belong to; never an end frame.
- **Glossary is shared** (`notation.json`): define once, reference by id —
  `<div data-formula="id"></div>` formula cards, `<span data-notation="id">`
  symbol popups. Symbol `{id, tex, name, say, category, meaning,
  explanation, example?, concept?, see[]}`; formula `{id, tex, name, say,
  meaning, parts[{tex, explain, symbol?}], concept?, conditions?, source?}`.
- **Story references are shared** (`lore.json`): `<span data-person="id">`
  bio popups, `<span data-theorem="id">` statement popups. Person
  `{id, name, dates, famous_for, text, wiki?}`; theorem `{id, name, text,
  tex?, status?}`.
- `site/map.js`, `site/notation-data.js`, `site/lore-data.js` and
  `concepts/*/index.html` are generated — don't edit them.

## Verification

```
python tools/build.py            # validate and regenerate
python tools/build.py --check    # CI-style: also fails on stale generated files
```

Pages open straight from disk; KaTeX loads from a CDN (formulas need a
network connection), everything else works offline.

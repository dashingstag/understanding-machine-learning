RoPE: rotate by position

Attention is order-blind

Did you know?

Shuffle an attention layer's inputs and the outputs shuffle identically — a permutation-equivariant machine. "Dog bites man" and "man bites dog" are the same bag until order is injected.

In the real world

Early BERT/GPT-2 used learned absolute positions — a hard cap on context length. Everything modern uses relative schemes: RoPE in Llama/Qwen/DeepSeek, ALiBi in MPT.

Self-attention computes pairwise scores — see the mechanism — and pairs carry no order. Position must be smuggled in as data: added to the embeddings, or baked into the Q/K geometry.

RoPE — position as rotation

Did you know?

RoPE is parameterless — a fixed rotation schedule. It survives because it encodes what attention actually wants: distance, not address. Two tokens 5 apart always get the same relative angle, wherever they sit.

Pair up each query's coordinates; rotate pair $i$ by angle $m\theta_i$ where $m$ is position. The score $\mathbf{q}_m^\top\mathbf{k}_n$ then depends only on $m-n$ — attention becomes a function of offset. The panel shows one 2-D pair rotating as position grows.

Why this sets the context limit

Did you know?

Lost-in-the-middle showed models over-attend to the edges of long contexts — a positional pathology, not a knowledge one. Fix the encoding (NTK/YaRN rescaling) and context windows stretch 4k → 1M.

In the real world

'1M-token context' marketing is largely a positional-encoding story: rescale RoPE frequencies so unseen positions land on seen phases — then fine-tune briefly. See inference efficiency for the memory cost that remains.

Training at 4k bakes in a phase range; at position 4,001 the rotations hit untrained angles and attention scrambles. Frequency interpolation and NTK-aware scaling remap long positions onto trained phases — cheap, post-hoc, and now standard.
